## the job

A model on its own is a puppet on the floor. Capable, but nothing holds it up. I build the strings: the tools it can call, the memory it keeps, the middleware between them, the sandboxes it runs in, the evals that grade it. And a person's hand on the bar. That's the harness.

## how I build a run

My pattern for long-running agents. The same shape works for research, coding or document agents.

  1. A task comes in. Big, messy, long-running.
  2. The lead splits it between workers.
  3. One worker hits something it shouldn't guess.
  4. So the run stops, saves a checkpoint, and asks a person.
  5. The answer comes back. The show picks up where it stopped.
  6. Every step leaves a trace I can grade.

## the crew behind the show

The puppets get the applause. The crew makes the show work.

  • Prop master, tools and permissions: I design the tools an agent can pick up, and what it's allowed to do with them. One action at a time, each with a receipt. (Clicky Local)
  • Librarian, retrieval: the agent should read the right page, not every page. I build retrieval that keeps each tenant's documents to itself. (Multi-Tenant RAG)
  • Script supervisor, memory and context: I decide what stays in context, what gets summarized, and what gets saved for later.
  • Stage manager, sandboxes and shipping: agents run real code in a sandbox they can't break out of, shipped so the same run behaves the same way twice.
  • Critic, evals and traces: I read traces and score runs, so a fix is measured, not guessed.

## found, missed, invented

I read traces until the agent's mistakes have names. Every graded run sorts its output into three boxes: what it found, what it missed, and what it made up. Then I fix the prompt, the skill or the tool. Not the grader.
